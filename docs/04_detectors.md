# 4. Детекторы ПДн (Detectors)

Сервис `PDNDetectors` (`app/services/detectors.py`) инкапсулирует логику поиска совпадений по переданным строкам.

## Поддерживаемые типы

Типы загружаются из `RegexRule` (таблица `regex_rules`):

| Тип | `pdn_type` | Описание |
|-----|-----------|----------|
| Phone | `phone` | Мобильные и городские номера (7XXXXXXXXXX) |
| Email | `email` | Адреса электронной почты |
| Credit Card | `card` | Номера банковских карт (PAN, Luhn) |
| FIO | `fio` | Русские ФИО (интеллектуальный парсинг) |

Пользовательские типы добавляются через UI/Настройки → Регулярки ПДн → Добавить (сразу создаёт флаг `is_{type}` в `system_settings`).

## Интеллектуальный алгоритм поиска ФИО

Класс `PDNDetectors` содержит следующие вспомогательные методы:

| Метод | Описание |
|-------|----------|
| `detect(text, field_path, rules)` | Основной метод: применяет regex, исключения, возвращает список совпадений |
| `_is_surname(word, surn_ends)` | Проверка окончания слова на фамильные суффиксы (словарь из настроек) |
| `_is_patronymic(word, patron_ends)` | Проверка окончания слова на отчественные суффиксы |
| `_is_initials(word)` | Распознавание формата `И.О.` или `И. О.` (regex: `^[A-ZА-ЯЁ]\.\\s?[A-ZА-ЯЁ]\.$`) |
| `analyze_fio(text, surn_ends, patron_ends)` | Основной метод поиска ФИО — токенизация текста и проверка по паттернам |

### Поддерживаемые порядки ФИО

Метод `analyze_fio` проверяет по нескольким паттернам одновременно:

1. **Фамилия Имя Отчество** — 3 слова, w1=фамилия, w3=отчество
2. **Отчество Фамилия Имя** — 3 слова, w1=отчество, w2=фамилия
3. **Имя Фамилия Отчество** — 3 слова, w2=фамилия, w3=отчество
4. **Фамилия И.О.** — 2 слова, w1=фамилия, w2=инициалы
5. **И.О. Фамилия** — 2 слова, w1=инициалы, w2=фамилия

Для группы из 2-3 последовательных токенов (заглавные слова) каждый сверяется со словарями фамилий и отчеств по окончаниям.

## Фильтрация по исключениям (Exclusions)

Типы исключений из `RegexRule` (`rule_type`):

| `rule_type` | Описание |
|-------------|----------|
| `regex` | Основной паттерн для типа ПДн (системный или пользовательский) |
| `exclude_pattern` | Глобальное исключение по полному совпадению или подстроке для значений |
| `prefix_exclude` | Исключение по префиксу значения |
| `suffix_exclude` | Исключение по суффиксу значения |
| `exclude_key` | Исключение конкретного ключа везде |
| `exclude_index_pattern` | Исключение индекса по точному совпадению или подстроке |
| `exclude_index_regex` | Исключение индекса по регулярному выражению |
| `include_index_regex` | Включение индекса по регулярному выражению |
| `mail_service_name` | Почтовые домены считающиеся за валидный email |
| `unknown_mail_service_part` | Неизвестные/специфичные почтовые домены для аналитики |
| `card_bank_bin_4` | 4-х значные БИНы банковских карт (в основном РФ) |
| `surn_end_cis` | Типичные окончания фамилий СНГ для ФИО |
| `surn_end_world` | Западные/Европейские окончания фамилий для ФИО |
| `patron_end` | Окончания отчеств для ФИО |
| `fio_special_marker` | Спецмаркеры ФИО (оглы, кызы, фон, ван) |
| `invalid_def_code` | Невалидный DEF-код для телефонов |

## Индексные исключения

Per-index исключения через `IndexKeyExclusion` (`/api/v1/settings/exclusions/index`):
- Позволяют игнорировать конкретные JSON-пути (`key_path`) для выбранного `index_pattern` и `pdn_type`.
- Применяются **перед** проверкой детектором — исключенные пути пропускаются.

## Нормализация словарей

При сохранении через Frontend/настройки:
- Все строковые словари ПДн (кроме `unknown_mail_service_part`) автоматически:
  1. Приводятся к нижнему регистру
  2. Сортируются по алфавиту
  3. Очищаются от дубликатов
- Детекторы используют `lower()` для сравнения
- В БД `PDNFinding.raw_value` оригинальный регистр найденной строки сохраняется неизменным
